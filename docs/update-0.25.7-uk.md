# Ribterra 0.25.7 — Адреси та підключення через різні мережі

Виправлено вибір адреси запрошення: активний мережевий адаптер зі шлюзом показується перед віртуальними адаптерами без шлюзу. Раніше кнопка могла копіювати адресу VirtualBox Host-Only, недоступну другому фізичному ПК. Лобі тепер містить список адаптерів: виберіть потрібну LAN або VPN адресу перед копіюванням.

Повідомлення очікування відповіді хоста відокремлено від завантаження світу. Після тайм-ауту гра пояснює, що потрібно перевірити адресу, запущену кімнату та доступність хоста між мережами.

## Два комп’ютери в різних мережах

Ribterra використовує пряме UDP-підключення. Автоматичного інтернет-реле чи пробивання NAT у цьому випуску немає. Оновлення вибору адреси саме по собі не робить локальну адресу доступною через інтернет.

Можливі два способи:

1. Спільна VPN: обидва ПК приєднуються до однієї приватної мережі, наприклад Radmin VPN. Хост створює кімнату в Ribterra. Другий гравець вводить VPN-адресу хоста та порт, типово `:27020`. Потрібна VPN-адреса, а не Wi-Fi чи VirtualBox.
2. Пряме підключення: хост має доступну зовнішню IP-адресу; UDP-порт 27020 перенаправлений на його локальну адресу, а Windows Firewall дозволяє Ribterra приймати цей трафік. Другий гравець вводить зовнішню IP-адресу з портом. За CGNAT одного правила домашнього роутера недостатньо; потрібна доступна адреса від провайдера або VPN.

На ПК хоста потрібно натиснути «Створити кімнату» або «Продовжити світ» і залишити її відкритою. Сам екран «Створення та підключення» ще не запускає сервер.

## Пряме підключення через роутер

На роутері хоста потрібне правило Virtual Server / Port Forwarding: протокол **UDP**, зовнішній порт **27020**, внутрішня адреса — поточна LAN-адреса ПК хоста, внутрішній порт **27020**. Для стабільної адреси ПК можна використати DHCP reservation. Дозвольте вхідний UDP 27020 для фактичного `Ribterra.exe` у Windows Firewall.

У друга в полі адреси сервера має бути `зовнішня_IP_хоста:27020`. Адреси 192.168.x.x і VirtualBox не маршрутизуються між різними мережами через публічний інтернет. Порівняйте WAN-адресу роутера із зовнішньою адресою з’єднання; додатковий NAT потребує налаштування попереднього роутера або допомоги провайдера. Успіх підтверджує підключення Ribterra з іншої мережі; звичайна TCP-перевірка порту не перевіряє цей UDP-протокол.

Для Zyxel USG FLEX у Nebula: Configure → Firewall → NAT → Virtual Server. Офіційна [інструкція Zyxel](https://community.zyxel.com/en/discussion/14227/atp-flex-how-to-configure-a-nat-rule-virtual-server-on-nebula) пояснює поля Public IP/Port, LAN IP/Port і перевірку додаткового NAT.

Офіційна інструкція Radmin VPN: https://www.radmin-vpn.com/help/

Збереження та мережевий протокол сумісні з 0.25.6. Параметри роутера, VPN і системного брандмауера гра автоматично не змінює.
