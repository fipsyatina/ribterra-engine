# Повний рушій Ribterra: вимоги й докази приймання

Активна ціль: реалізувати рушій повністю за `Ribterra_Development_and_Steam_Plan_UA.docx`, редакція 1.4. Початковий M0 та наступна серверна основа є проміжними станами. Ціль не завершена, доки кожен обов'язковий рядок нижче не має актуального виконуваного доказу. «Файл існує», «залежність встановлено» або «бібліотека компілюється» не означає готової можливості гри.

Авторитетне джерело: [оригінальний DOCX](source/Ribterra_Development_and_Steam_Plan_UA.docx), текстова копія [development-plan-ua.txt](source/development-plan-ua.txt). Посилання `L` нижче — рядки цієї незміненої копії. Концепт-арти в `source/concepts` є референсами, не скриншотами реалізації.

Статуси: **M0 частково** — початкова механіка прототипу; **у роботі** — частина вимоги реалізована, повний gate ще не пройдено; **очікує** — необхідна функція ще не реалізована. Лінійку **0.10 завершено збіркою 0.10.1**: черги ручних наказів, часткові результати груп, серверне керування мешканцями, автоматичне відновлення сесії та доставка snapshot після затриманого ACK навіть на паузі. Save8/protocol7/rules7/generator2 збережено. Локально — 52/52 CTest, два остаточні UDP-профілі 150 мс RTT і 1%/3% втрат, GPU-перевірка 36 кадрів і 4/4 package smoke. Фінальний CI `13ed5c2` — Windows 52/52, Linux 35/35, UBSan 13/13 без C++ warnings/errors. Пакет і launcher 0.10.1 відповідають цьому runtime; деталі перегляду кадрів та межі тестів — у [VALIDATION.md](VALIDATION.md). Контракт — [MANUAL_ORDERS.md](MANUAL_ORDERS.md). Повний рушій і всі вимоги нижче лишаються чинними.

Історична 0.8 має локальні 40/40 CTest, GPU у 5 мовах, benchmark і package smoke; CI source commit `f62cea0` — Windows 40/40, Linux 26/26, UBSan 8/8. Попередня 0.7 має локальні 37/37 CTest, GPU у 5 мовах, carrying save/resume, package smoke й CI Windows 37/37, Linux 24/24, UBSan 7/7. Це історичні докази відповідних версій, а не поточного коду 0.10 або повного рушія; актуальне приймання — у [VALIDATION.md](VALIDATION.md).

## Поточна послідовність реалізації

1. Foundation, version/hash/ID, atomic filesystem, pinned dependencies, structured save і wire schemas.
2. Authoritative GameServer і переведення на нього існуючого ігрового клієнта; тестування command auth/dedupe/resources/visibility.
3. Реальний standalone GNS, visible full/delta, reconnect, dedicated, LAN discovery, chat UI, durable session/autosave.
4. SDL_GPU/Renderer2D, shader/asset pipeline та RmlUi/ICU/miniaudio без залежностей у SimCore.
5. Chunks/EnTT/логістика/AI/населення, карти й дипломатія, бій/здоров'я/суспільство/події — вертикальними сценаріями зі збереженням і multiplayer перевіркою.
6. Повний scale/performance/portability gate, Steam adapter і реальні зовнішні інтеграційні перевірки.

## Зовнішні дії

Steam Direct fee, AppID/onboarding, податкові й банківські дані, store review, Coming Soon та публікація (L750–780) — окремі зовнішні дії. Наявність цих пунктів у документі не є дозволом здійснювати платіж, подавати юридичні дані чи публікувати гру. Вони не заважають реалізації direct/LAN та решти локального рушія. Steam-функції залишаються неперевіреними без SDK/AppID і реального тесту.

## Правило закриття цілі

Усі обов'язкові вимоги документа зберігаються в scope: 38 вихідних рядків та 3 доповнення V01–V03, разом 41 вимога. Жоден частковий рубіж 0.10 не означає завершення повного рушія. Невиконані рядки не вилучаються й не перейменовуються на необов'язкові через завершення проміжної збірки. Підсумкова заява «рушій повністю готовий» вимагає повного gate L592–643 та L984–1000, актуальних доказів і явного переліку зовнішніх обмежень.
