- Це також правило для наступних агентів у кореневому [AGENTS.md](../AGENTS.md), а не лише рекомендація для одного очищення. Після перевіреної заміни прибирати повідомлені застарілі повні копії до накопичення наступних версій; не створювати повний runtime на кожну тестову спробу.
- Для нової версії лишати актуальний придатний до запуску пакет і одну попередню перевірену версію для відкату. Пакет, на який указує будь-який чинний launcher, не видаляти без узгодженої заміни цього launcher.
- Після успішної заміни збірки не залишати додаткові повні копії її програм у кожному тестовому каталозі. Зберігати компактні звіти, hashes, потрібні контрольні PNG та відтворюваний код перевірки. Історичний звіт не означає, що його executable збережено назавжди.
- Для поточних ізольованих engine-перевірок лишаються ліміти 128 MiB логічних даних на root і щонайменше 384 MiB вільного місця. Перед створенням чергового root перевіряти потребу в попередніх; після проходження заміни готувати очищення застарілих копій.
- Невдала спроба залишається до діагностики й підтвердження виправлення. Потім достатньо необхідного компактного відтворюваного доказу; не накопичувати нескінченно її об'єктні файли, DLL та дублікати експортів.
- Не видаляти за загальним шаблоном `artifacts/*`, `build/*` чи `*runtime*`. Вихідний код, оригінали арту, концепти, збереження гравця та чинні залежності поточної перевірки — окремі захищені дані.

Повторний read-only вимір 08.10.2026: `artifacts` містить 35 130 файлів, **29 027 714 006 логічних байтів (29,03 GB / 27,03 GiB)**; reparse-переходів не виявлено. Це поточний розмір після попереднього очищення, не нове звільнення місця. У цьому повторному вимірі жодного файла не видалено й нічого не опубліковано на GitHub.

## Перед кожним очищенням

1. Виміряти конкретні каталоги, визначити актуальні launcher і залежності перевірок, відокремити оригінали від згенерованих копій.
2. Створити точний dry-run manifest з абсолютними шляхами, розмірами та SHA-256. Перевірити належність до явного allowlist і відсутність reparse/symlink-переходів.
3. Повідомити користувачеві конкретні шляхи/manifest, обсяг, причину та можливість відновлення **до** видалення. Це правило діє також для кешів і тимчасових файлів. Поточний дозвіл на очищення старих версій не дозволяє прихованого видалення інших даних.
4. Видалити тільки повідомлені цілі після повторної звірки. Записати фактичний результат, перевірити захищені файли та повідомити фактично звільнене місце.

## Обмежене очищення історичних test runtime

`tools/prune_artifact_runtime_copies.ps1` працює лише з явним списком історичних тестових cohorts 2026-10-05–07. За замовчуванням він **тільки** створює dry-run manifest. `-Apply` потребує SHA-256 повідомленого manifest; перевіряє кожний файл до й безпосередньо перед видаленням. Скрипт видаляє лише копії `.exe/.dll/.lib/.pdb/.obj/.ilk/.exp`, не видаляє каталогів, PNG, texture assets, source snapshots, reports чи save-файлів. Це не універсальний автоматичний cleaner для майбутніх версій.

Очищені executable-копії не можна повторно використовувати для історичного прогону. Для нової заяви потрібна нова обмежена збірка/перевірка. Компактні збережені звіти залишаються історичними, не поточним підтвердженням готовності двигуна.

За замовчуванням створюється лише новий dry-run manifest; Apply потребує його повідомленого SHA-256 і незмінного helper. Захист охоплює всі нецільові файли цих roots, повністю latest attempt10 і rollback attempt05, GameView engine build/native roots та чинні launcher targets.
