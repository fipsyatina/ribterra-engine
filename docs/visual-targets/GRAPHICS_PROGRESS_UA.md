## What changes at each step
V-numbers are internal visual stages, not a new public 0.26.x release numbering. For the base graphics branch, this order takes precedence over the old “Full Dynamic proof before HUD” sequence: the user deferred Dynamic.

| Step | Visible change from the previous step | Preserved elements | Implementation and criteria |
|---|---|---|---|
| V00 — baseline | No change: existing UI/terrain/sprites | Unchanged real PNG | Capture provenance, commit/version; do not present a generated image as the baseline |
| V01 — UI | Compact resources; the lower inspector; the horizontal actions; removed the big right block | Existing terrain/plants/buildings/residents, daylight | RmlUi/RCSS/GameUi, real data/commands, 720p/locales/input; The forecast is still hidden. |
| V02 — world and surface | Land with material transitions, groups of nature, river and shore | UI V01 and the old building/unit assets | Common terrain/path/build/picking rules, generator/version/save, no Road; 10 seed reachability, seamless shore |
| V03 — Buildings and people | Consistent building silhouettes, foundations, materials, readable residents/cargo | Map/Coast/UI of the previous steps | Small kit → runtime proof → available catalog/8 facings; Real jobs/cargo, without any new unforeseen building. |
| V04 — rain | Precipitation, wetter and darker materials, weather/temperature/forecast | The same UI zones, six buildings, map, and visible population | First WT simulation/save/net/current/forecast; then FX; pause/2×/reconnect, only real numbers |
| V05 — winter | Snow cover, snow, winter palette and weather warning | Location of objects and previous systems | Authority cover/melt, material masks, bounded FX, native transitions; Footprints require separate acceptance and are not automatically ready |
| DL — later | Dynamic reaction of land/façade/inhabitants to source + switch | Both modes have the same rules of the game | [Future plan](FUTURE_DYNAMIC_LIGHTING_PLAN_UA.md). Now just the scaffold; There's no single screenshot ready |

Rain/winter — two visible milestones, but shared authoritative weather dependencies can be realized with one prior technical package. Technical changes without noticeable difference do not produce a fictitious new beautiful frame.

## Specific tasks for agents
**V01:** to transfer HUD to the real RmlUi, rather than paint it PNG. Use the current resource/selection/command data. Maintain access to detail of the warehouse, construction and menu; Check the Escape/focus/mouse capture. Do not replace world graphics in this diff.

**V02:** align the renderer surface and the new valley with path/build rules. Remove the manual Road/bonus under the server/client compatibility contract. Do not change building footprints to match a painted shore. Select a demo seed, verify access to food/tree/stone/mine; then implement material transitions and vegetation.

**V03:** calibrate export camera/pivot/scale on one building; make house/store/workshop kit and resident, check the motion on V02. Then spread the style to the available types, House II/Workshop II, construction/winter/selection. Models in this branch mean the appearance of objects and production masters; A transition to a full 3D runtime was not requested.

**V04:** pass the [weather spec](../../.omx/plans/2026-09-26-weather-implementation-spec-ua.md) to show the °C and forecast. Rain comes from the host state, wetness is not invented by the client. Persistent puddles, physical flooding and dynamic reflections are not added hidden. Rain in the mockup shows the desired appearance; video must establish actual motion.

**V05:** use the same scene in winter, with snow on eligible surfaces and coordinated coverage/melting. Do not freeze water or add insulation/fuel/HP damage. The footprint cache is separate work from [World FX](WORLD_FX_SPEC_UA.md); a snow texture alone does not implement it.

## The rule of comparison
For each step, capture the previous and new executable with the same seed/save, camera center/zoom, resolution, UI scale, and simulation state. Record only the actual difference beneath each frame. If V01 suddenly includes a new river or models, the evidence is invalid; separate the implementations and captures. For V04/V05, weather is the controlled variable.

The six UI zones and overall art direction come from the user's concept. The result does not have to reproduce every AI-generated pixel; it must prove the described materials, scale, function, and state.
