# Ribterra 0.26.3 concept-rebuild preview — межі та непідтверджені пункти

## Статус

Це локальне прев’ю переробки V01–V03, а не опублікований реліз. Новий арт і функціональні зміни інтегровані у вихідну гілку, але точна відповідність target-0261/0262/0263 ще не прийнята. Поточний статус: **REBUILD / не прийнято**. На 05.10 повний suite — 92/92, native matrix — 60/60; після подальших змін їх потрібно повторювати. Технічний PASS не є художнім прийманням.

- Остання інкрементальна збірка завершила **40 targets** без помилок; повний 92-test suite лишається окремим pending доказом.
- `matrix-twelfth-atlas`: quick **5/5** (13 native D3D12 captures) і `art-twelfth-d3d12` exit 0 на наборі з 183 assets, content hash `112d8f79c132f87e4e6d197e40c821503575022c7b94c5d82f941878bb49185e`. Ці результати підтверджують окремі локальні контракти, але не є художнім прийманням, повним latest-runtime PASS або доказом готовності релізу.

## Що вже є у поточній реалізації

- версія гри 0.26.3;
- save format 8, rules 18, generator profile 7, network protocol 21;
- випадковий seed для кожної звичайної нової гри та відтворюваний явний `--seed`;
- звичайний старт із Табором і 10 мешканцями;
- новий HUD, шрифти, іконки та арт природи, споруд, будівництва, сезонних станів і мешканців;
- висотний рельєф, змінна річка, змішані ресурсні ділянки й природні стежки від фактичного руху;
- F1 приховує та повертає весь HUD; F12 зберігає справжній кадр запущеної гри;
- старі підтримані світи зберігають свій generator profile і не перегенеровуються потайки.

## Що ще потрібно довести перед прийманням

1. Порівняти свіжі нативні кадри звичайного старту, розвиненого поселення і зими поруч із відповідними концептами.
2. Перевірити композицію HUD, читабельність, портрети, мінікарту, контури вибору та відсутність перекриттів у цільових роздільностях і масштабах UI.
3. Перевірити в грі всі доступні споруди, House II/Workshop II, три стадії будівництва, літні та зимові стани без повернення старого арту.
4. Перевірити напрямки ходьби, масштаб людей, правдивий вантаж, доставку та перекриття мешканців об’єктами.
5. Перевірити накопичення й save/load природних стежок після реального руху, а не через постановочне редагування карти.
6. Повторити повний тестовий набір після остаточної інтеграції активів та виправити всі відмови.
7. Окремо виконати кооперативний сценарій на двох фізичних Windows-ПК через реальну мережу. Локальні два клієнти на одному ПК цього не доводять.

## Свідомо відкладено

Чотириденний прогноз, температура, дощ, буря, накопичення погоди та повне динамічне освітлення належать до V04 і пізніших етапів. У 0.26.3 не можна підміняти їх декоративними числами або погодними повідомленнями з концепт-арту.

## Умови безпечної перевірки

- Перед відкриттям важливого старого світу скопіюйте його файл з `%APPDATA%\Ribterra\Ribterra` в окреме місце.
- Не перезаписуйте єдину резервну копію через F5, доки не перевірите завантажений світ, рельєф, споруди й мешканців.
- Для повторюваного порівняння використовуйте один явний seed; для перевірки випадковості створіть кілька звичайних нових ігор без `--seed`.
- Не видавайте постановочне розвинене поселення за звичайний старт: звичайний старт — лише Табір і 10 людей.
- Для мережевої гри використовуйте однаковий локальний пакет на клієнті й сервері. Protocol 21, rules і content мають збігатися.

Прев’ю вважається прийнятим лише після свіжих нативних кадрів, повторного повного тестового прогону та закриття наведених пунктів. Сам факт наявності нових активів або успіх окремих focused-тестів не підтверджує ідеальну відповідність концептам.
